# SheetFlow — План продукту

## 1. Аудиторія

**Первинна:** малі бізнеси 5–50 людей, які бігать операційні процеси
(закупівлі, замовлення, виробництво, логістика) в Excel/Google Sheets.
Власник або ops-менеджер — «людина-Excel» у компанії.

**Сегменти:**
- оптова торгівля та дистрибуція (облік замовлень і відвантажень);
- мале виробництво / майстерні (замовлення-наряди, статуси виконання);
- сервісні компанії (заявки, виконавці, дедлайни);
- агробізнес та імпортери (партії, поставки, оплата).

**Біль користувача:** «наш процес надто кастомний, жоден інструмент не підходить»,
немає аудит-трейлу, файли `final_v7_latest_final.xlsx`, паніка коли
ops-lead у відпустці.

## 2. Ціннісна пропозиція

Не «переїдьте на нашу CRM», а «принесіть свій Excel — ми зробимо з нього додаток».
Zero-switching-cost onboarding: цінність з перших 10 хвилин, без міграції,
без консультанта, без зміни звичок команди.

## 3. MVP scope (поточна реалізація)

| Функція | Статус |
|---|---|
| Завантаження `.xlsx` (openpyxl), розбір колонок + прев'ю | ✅ |
| Майстер мапінгу колонок на сутності (item, quantity, status, assignee, due_date, amount) | ✅ |
| Валідація типів (int, float, дата у 6 форматах), звіт про помилки по рядках | ✅ |
| Колекція = таблиця з фільтрами (статус, виконавець, пошук, лише прострочені) | ✅ |
| Зміна статусу через dropdown | ✅ |
| Audit log: хто/коли/що змінив, кожна зміна → `audit_events` | ✅ |
| Просрочені `due_date` підсвічені червоним (не в статусі done) | ✅ |
| CSV export назад (UTF-8 BOM — коректно відкривається в Excel) | ✅ |
| Перший користувач = admin, сесійні токени | ✅ |
| UI: одна сторінка HTML + vanilla JS, без build | ✅ |

**Поза MVP:** багатокористувацьість з ролями, редагування всіх полів з UI,
вкладення/коментарі до рядків, інтеграції (Google Sheets, Telegram),
сповіщення email/Telegram, повторювані імпорти (delta sync).

## 4. Архітектура

```
Браузер (1 HTML + vanilla JS, fetch API)
   │  JSON over HTTP
FastAPI (app/main.py) ── маршрути, валідація pydantic
   ├── app/importer.py ── парсинг xlsx, мапінг, валідатори типів
   └── app/db.py ── SQLite (stdlib): users, sessions, collections,
                     rows, audit_events
```

- **Дані:** 5 таблиць, JSON-mapping колекції зберігається у `collections.mapping_json`.
  Рядки — у фіксованих типізованих колонках (швидкі фільтри SQL).
- **Аудит:** один вектор запису `db.audit()` — кожна зміна стану проходить через нього.
- **Імпорт:** двоетапний (upload → map), файл тримаємо в пам'яті до мапінгу.
- **Розгортання:** single binary/folder + SQLite файл; бекап = скопіювати .db.

## 5. Roadmap

| Фаза | Що | Критерій виходу |
|---|---|---|
| MVP (0–1 міс) | імпорт → мапінг → колекція → аудит → CSV | 3 пілотні компанії ведуть реальні процеси |
| v1.1 | роли та багатокористувацьість, редагування рядків з UI, повторний імпорт (upsert за ключем) | друга роль у пілоті, без data-loss при реімпорті |
| v1.2 | сповіщення (email/Telegram про прострочені), шаблони дашбордів | ops-lead у відпустці — процес не зупиняється |
| v2.0 | інтеграції Google Sheets/1C, API для партнерів, SaaS-мультиарендність | 10 платних команд |

## 6. Монетизація

- **Self-hosted license:** одноразова оплата за інсталяцію (орієнтир $99–$249)
  + річна підтримка/оновлення (20%). Для бізнесів, що не люблять хмару.
- **SaaS (пізніше):** $15–29/міс за команду залежно від розміру та кількості
  колекцій; free tier — 1 колекція, 500 рядків.
- **Оновлення-канал:** платні конектори (1C, BAS, Google Workspace) як add-on.

## 7. Ризики

| Ризик | Ймовірність | Мітигація |
|---|---|---|
| Користувачі «затикаються» на мапінгу (не розуміють сутності) | середня | автопідказка мапінгу за назвами колонок (fuzzy-match), відео-туторіал 2 хв |
| Excel-файли занадто «брудні» (merged cells, кілька шапок, формули без значень) | висока | детектор «бруду» з порадами; ручний вибір рядка-шапки у v1.1 |
| Люди повертаються в Excel після пілота | середня | CSV-експорт з будь-якого подання (вихід завжди відкритий), біч-на-біч режим |
| Довіра: фінансові дані у невідомому сервісі | висока | self-hosted першим, експорт/бекап в 1 клік, відкритий код |
| SQLite-ліміти при >10⁶ рядків | низька (MVP) | переїзд на Postgres за прапорцем у v2 |
